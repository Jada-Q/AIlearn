# Harness 定下限，模型定上限：续拆 DeepSeek Harness 的压缩、缓存与工具流水线

> 2026-08-15 · 续 [33 — 拆开 agent 的身体](./33-agent-harness-anatomy.md)，源码范围扩到 compaction 与 tools 两个子系统，外加三个行业判断

上一篇拆了 agent loop：一行 while、账本原则、Esc 只掐未来不掐过去。这一篇继续往下读了两个子系统（`packages/compaction/`、`packages/core/tools/`），把账本原则一路推到它的三个推论，最后给出这套学习的总公式——以及它的一个重要例外。

---

## 一、压缩：不是删除，是"贴便签遮住"

AI 聊久了会"变笨"，根源上一篇讲过：账本只增不减，每步都重发全部历史，塞爆是结构必然。所有 harness 的解法都一样——压缩（compaction）：把较早的一段历史让模型摘要成一段话，替换掉原文的位置。

源码里的三个讲究：

**原文永不删除。** 被压缩的记录还在日志里，只是不再寄给模型——像在账本某几页上贴了张摘要便签，原页还在下面。为什么不删？账本原则：删了原文，崩溃后重放日志就不确定了，审计也没了。

**摘要伪装成 user 消息。** 模型的世界里只有 user / assistant / tool 三种角色，"前情提要"没有专属角色，只能借用户的嘴说。

**连锁都是用账本做的。** 压缩开始记一条 `compaction/start`，结束记 `compaction/end`。中途崩溃会留下一个"没闭合的 start"当可检测的遗留物——宁可留下"我可能没做完"的证据，绝不写下"我做完了"的谎言。和 Esc 那课同一个哲学。

**推论（对每个用 AI 干活的人）**：压缩是拿细节换空间的有损交易，摘要里没写的就是没了。所以重要的事实必须写进文件（配置、文档、外部记忆），不能依赖"它记得聊过"——**对话历史是注定被有损压缩的介质，文件不是。**

## 二、缓存：压缩省 token，但压完第一刀最贵

一个反直觉事实：compact 是为了省钱，压完之后的第一条请求反而更贵。

机制是前缀缓存（prompt caching）：服务商对"和上次请求逐字节相同的开头"直接用缓存计价（Anthropic 公开定价约为正常输入价的 1/10）。账本只增时，前缀永远不变，缓存一直命中——所以"每次寄全本"没有想象中贵。压缩把历史中间几页换掉了，从改动点起缓存全部作废，第一条请求整本全价重算，之后缓存重建。

类比：复印店对"和上次一样的前 N 页"留了存版直接印，半价；你换了第 3 页，存版报废，这次整本重新制版。

**推论**：账本只增 = 能恢复 + 能省钱；改账本的那一刻付全价。实操上：同一个会话连续干活比反复开新会话省钱，/compact 不要闲着没事按。

## 三、工具流水线：安全的三个设计智慧

模型说"帮我跑这条命令"之后，这个调用要过六道站：pre-execute 安检口（允许/拒绝/询问）→ 守卫 → 环绕包装（超时/重试）→ 工具本体 → post-execute 质检口 → 只读公示。三个值得抄进任何系统设计的细节：

**1. "要问"没人接，就当"不行"。** 权限弹窗出生在第一站，返回值只有 allow / deny / ask 三种。如果部署环境没装审批组件（无人值守脚本），ask 自动退化成 deny。没人在场时，安全的默认方向是关，不是开。

**2. 拒绝是单调的。** 任何一个守卫说"不行"，后面的监听器无法翻案。如果拒绝可以被翻回来，安全结论就取决于插件加载顺序——顺序变了，危险命令就放行了。安全决定只能收紧，不能放松。

**3. 藏起来不等于禁止。** 源码文档原话："这是实时可见性组合，**不是权限边界**。"把工具从模型的菜单上藏掉 ≠ 厨房做不出这道菜；真正的禁止必须在执行那一站拦。推广开:**概率性防御（提示词里写"不要做 X"）和确定性防御（执行层拦截 X）是两个物理层级**,前者管不住的,后者管。

还有一个并发设计:**拍照可以齐跑,施工必须排队**。能并行的唯一条件是工具自己声明"并发安全"(读文件=拍照,不改变世界);没声明、声明失败的一律按独占排队(跑命令=施工)。白名单思维:想快必须自证无害。两条部署命令齐跑的最坏结果不是慢,是竞态——各写一半、产物碎片化、且下次复现不出来。

## 四、三个行业判断

**1. 免费的是身体，涨价的是大脑。** Harness 开源的同一晚，DeepSeek 上线 V4-Pro 且 API 提价（VentureBeat 报道）。剃刀免费、刀片收钱：harness 生态越繁荣，模型 API 的定价权越强。开源不是慈善，是漏斗。

**2. 官方明说"现在别托付"。** repo 根文档白纸黑字：预览版、数据格式零兼容承诺、"Backends reject old on-disk formats"。今天存进去的会话和配置，下个版本可能拒读。评估任何 v0.x 基础设施时，先找它的兼容承诺条款。

**3. 真正的野心是"agent 改自己"。** 官方命令里有一条 demo，注释原话："the agent modifies its own runtime"。"一切皆插件"的终点想象不是方便人配置 agent，是方便 agent 配置自己。兴奋与警惕各半：能自我改装的机器进化更快，但你焊的每道安全门理论上都是它能拆的零件——给"会改自己的系统"设不可拆的底线，会是未来几年最重要的工程课题之一。

## 五、总公式，和它的例外

> **Harness 定下限（不崩、可恢复、可取消、不乱来），模型定上限（聪不聪明）。换更好的 harness 不会让 agent 更聪明，只会让它死得少。**

例外：有初步研究提示（未验证），模型越弱，换好 harness 带来的提升越大。直觉上讲得通——检查清单对新手的提升远大于对老手，**脚手架对越不会走路的人，越接近能力本身**。所以精确版是：模型越强，这条公式越准；模型越弱，harness 越会"越界"去补上限。
