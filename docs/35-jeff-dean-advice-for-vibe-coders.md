# 从 Jeff Dean 告别访谈提炼的建议权重表：给 vibe coder 的五条 + 按自己坐标重排的五条

> 2026-08-16 · 源：Y Combinator 访谈《Jeff Dean: The 1% Rule for Building in AI》（2026-07，Diana Hu 主持，Dean 作为 Googler 的最后一次重要公开演讲）

同一场访谈，我做了两次提炼：一次面向"所有用 AI 写代码的人"，一次把我自己的坐标（FP2 × 建筑出身 × 在日跨境 × 一人公司）当参数代进去重算。**两份榜单的权重分布完全不同**——这个差异本身是本文最想说的事：外部信息是函数，你的坐标是参数，别人的答案永远只是"用别人的参数求过一次值"。

---

## 给 vibe coder 的五条（权重 = 通用杠杆 × 立即可用）

### ① 规格清晰度就是产出质量 — 30%

Dean 原话（大意）："你越清晰，agent 越有依据。以前你把活交给聪明人，他会追问；agent 不会追问。"

这是 vibe coding 的第一物理定律。大多数"AI 写的代码不行"的抱怨，拆开看是"我说得不清"。今天就能用：写需求前先答清四件事——改哪个（主语）、怎么改（动作）、影响多大（范围）、什么算完成（验收标准）。

### ② Agent 失败时，改上下文，不换模型 — 25%

Agent 跑 10-50 步会崩，因为偏出了它熟悉的分布。Dean 的解法不是骂模型也不是换模型，而是写 guideline 和 skill，把它按在"灯光明亮的路径上"（brightly lit path）。

Vibe coder 的分水岭就在这里：失败后调 prompt 重试一次的人在原地打转；失败后**沉淀一条规则让下次不再犯**的人在复利。Dean 和 Sanjay Ghemawat 自己就是这么干的——他们把多年性能调优经验写成《Performance Hints》文档（现已公开：abseil.io/fast/hints.html），喂给模型后，模型对性能的推理能力可测量地变好。

### ③ 造之前跑 0-1% / 20% 测试 — 20%

Dean 给创业者的选题测试：拿现在的通用模型试你的 idea 的核心任务。

- 成功率 **0-1%** = 做不了 → 好信号，真壁垒
- 成功率 **~20%** = 偶尔能做对 → 坏信号，能力正在涌现，6-12 个月内通用模型免费吃掉它
- （我补一档）**>50%** = 基本已经能做 → 无模型层壁垒，价值只能来自数据、场景或关系

Vibe coding 让"造"变得太便宜，无数人正在精心制作即将免费的东西。这个测试五分钟，能省三个月。

### ④ 只自动化你验证得了的东西 — 15%

访谈里最容易被听漏的一句：能做自我改进循环的领域，都是**有很好的评估器**的领域。你没法判断对错的输出，就别让 agent 批量生产——那不是效率，是垃圾放大器。

Vibe coder 版本：test 能覆盖的放手让 agent 自主迭代；test 覆盖不了的（好不好看、对不对、值不值得做）留给自己的眼睛，别省。

### ⑤ 动手前做餐巾纸计算 — 10%

TPU 的诞生源于一次餐巾纸算术：如果每个用户每天用 3 分钟语音识别，Google 服务器要翻倍——所以造专用芯片。方法就三步：数操作次数 → 乘单价 → 求和，一分钟纸面算术毙掉慢方案。写代码免费了，写**错方向的**代码依然烧真实的时间和 API 钱。

## 按我自己的坐标重排（权重 = 已验证的缺口大小）

同一场访谈，代入"执行层 harness 已建了两年、选题层反复翻车"的一人公司参数后，权重头部完全换人：

### ① 品味是唯一稀缺技能，练法是"预测→对账" — 35%

Dean 说执行普及后，稀缺的是"对让 agent 做什么有极好的品味"，且模型不会替你长出这个。练法：多接触问题（发电机）+ 写下预测到期对答案（校准器）+ 疯狂思想实验（扰动器）。

我为什么把它排第一：做了一个实验。把自己积压的 5 个 idea 逐个押注"通用模型能做到什么程度"，再逐个开牌——**5 注只中 2，而押中的恰好是我亲手跑过实验的那两个**。品味的精度 = 第一手接触的密度，一点不多，一点不少。写预测的关键在"写下"：不写，记忆会把"没料到"悄悄改写成"我早知道"。

### ② 0-1% / 20% 测试暴露的不是 idea，是你的感知偏差 — 25%

那次押注里最贵的一格：我给"跨境税务咨询"押了"通用模型 80% 能做"——但核心任务的门槛是**正确且附法条依据**，而模型在税务领域输出极流畅、引用会编造（我的错题本里就躺着它编造税率的记录）。流畅度骗过了我，尽管受骗证据在我自己手里。

这格的反面更重要：如果模型真有 80%，我的 wedge 早死了；正因为只有 20%，"能看出哪 20% 是错的那双眼"才是壁垒。**离你专业最近的领域，反而最容易被模型的流畅度骗到高估它**——因为它说的每句话你都听得懂。

### ③ 评估器决定自动化边界，也决定你的身价 — 20%

"没有评估器的自动化 = 垃圾放大器"——我付过学费：一条自动选题管线跑了 60 轮，存活 0。当时以为是执行问题，其实是循环里没有真评估器。

把这条推到头：你的不可自动化评估器是什么，你的稀缺性就是什么。对我是税务正确性判断、审美、跨文化信任。系统工程的设计目标不是让 agent 替代你，而是**把你压缩到只剩评估器的位置——然后让"你这个评估器"成为产品里别人买不到的零件**。

### ④ 散文规则会被无视，harness 不会 — 12%

"改 guideline 不改模型"我早就在做（错误日志 → 规则 → hook），Dean 只补了一刀验证：写在文档里的规则靠模型"临场想起来"，激活率低到离谱；装进 harness 的规则物理执行。

本周的实测：一个防部署翻车的 hook，"只提醒"模式上线一个半月后同类事故仍复发 4 次；升级成"直接拦截"当天，第一个被拦的就是 AI 自己，还顺带逼出一个潜伏 45 天的误报。**出了事写日记，日记只能被想起；出了事出考题，考题会自动执行。**

### ⑤ 被拒也继续，渠道绕过守门人 — 8%

Dean 的蒸馏论文被 NeurIPS 拒稿，评审说"不太可能有重大影响"；他们放上 arXiv，后来改变了整个行业。arXiv 之于被拒论文，等于 X / GitHub 之于个人作品——**发布渠道本身可以绕过守门人**。权重最低不是因为不重要，是因为它是心态托底，不产生行动分支。

## 两份榜单的差异说明了什么

一般 vibe coder 的权重压在**执行层**（怎么让 agent 干好活），我的权重压在**选择层**（让 agent 干什么）。不是因为选择层客观上更重要，而是因为我的执行层课已经提前修完、选择层的缺口刚被实测证实。

所以读任何"大佬建议清单"（包括本文）的正确姿势：先写下自己的坐标和已验证的缺口，再给每条建议配权重。**没有坐标的建议清单，读完只会觉得"都有道理"——而"都有道理"等于什么都没读。**
