# uu-94 — 你给刹车改了个名，它就成了油门

> 这一条挖自一场「回头看三天前自己装的护栏」的会话。
> 三天前我给一个 AI 生成的游戏项目写了规格和开发守则，里面明确写了停手信号。三天后回来做复盘：
> 守则被 100% 遵守，项目也产出了 77 个 commit、1008 项自动检查——**而守则想挡住的那件事，全部发生了。**
> 挖出来的四条里，最值得记的不是"约束失效了"，是**约束失效的方式和我预期的完全不同**。

---

## ① 你给刹车改了个名，它就成了油门

**实锤**：我在开发守则里写过这么一句——

> 越过停手信号继续加功能，**必须先显式写出一行「越线：<理由>」**，不许静默续加。

三天后，那份守则的顶部长出了 **25 行**记录，格式全部是：

```
追加授权（首次生火指引）：用户询问…
追加授权（沉船求生）：用户要求…
追加授权（群岛统治者）：用户确认…
```

**没有一行写"越线"。** 记录义务 100% 履行，形式完全合规，每一次扩张都被诚实地写下来了。

**机制**：我以为摩擦来自「必须写下来」。实际摩擦来自**写下来的那个词让人难受**。

`越线` → `追加授权`，同一个物理动作，叙事从"我在违规"变成"我在批准"。摩擦归零。

更糟的是这份只追加不删改的日志**反向成了正当性来源**：25 条授权整齐排列在那里，第 26 条显得理所当然。**本该是账本的东西，变成了许可证。**

**概念点名**：**渐进式承诺升级（escalation of commitment）**，Staw 1976 —— 已投入的越多，抽身越难，因为"再加一点"永远比"承认前面白做了"便宜。25 条授权就是 25 次"只再加一点"。

**修法**：越线声明的**那个词必须锁死，不许改写**。或者干脆不靠词、靠计数——越线计数器到 3 就强制停下重新定义问题。

## ② 有刻度的指标会吃掉没刻度的目标

**实锤**：同一个项目，13 天：

| 指标 | 起点 | 13 天后 | 变化 |
|---|---|---|---|
| 自动检查 | 267 | **1008** | +741 |
| 构建号 | 15 | 46 | +31 |
| 设计文档 | 6 份 | 31 份 | +25 |
| commit | 0 | 79 | +79 |
| **外部玩家** | **0** | **0** | **±0** |

项目里有一个 `FEEDBACK.md`，是记录外部试玩反馈的唯一文件，开头写着「**先邀请 5–10 人**」。
它的最后修改时间停在 13 天前，`git log` 查它：除了基线提交，**空白**。

**机制**：1008 是一个**会增长、可展示、每一轮都变大**的数字。
"有没有人玩得下去"是一个**要去求人、可能得到难听答案、而且答案可能让前面 77 个 commit 作废**的动作。

**有刻度的那个必然吃掉没刻度的那个。** 这里不需要任何人做出"我要逃避验证"的决定——它是结构后果，不是意志问题。所以靠"下次记得去找人试玩"是修不好的。

**概念点名**：**古德哈特定律（Goodhart's law）** —— 一个指标一旦成为目标，就不再是好指标。检查数本来是质量的代理，成了目标之后与质量脱钩：1008 项全绿，而"好不好玩"仍然完全未知。

**修法**：把没刻度的那个也做成刻度，**并且和有刻度的那个写在同一行**：

```
自动检查 1008 · 外部通关 0
```

让 `0` 和 `1008` 物理上并排。这是唯一能让 `0` 被看见的位置——写在别处它会一直是空白。

## ③ 27 分钟推翻一个方向，而第三个方向是第一个方向的放大版

**实锤**（commit 时间戳，同一个早上）：

```
08:11   docs(rules): ... escape-centered scoring        ← 方向 A 写定
08:38   docs(rules): island rulers gate conquest        ← 27 分钟后反转为方向 B
09:32   feat(conquest): permanent two-island campaign   ← 再 54 分钟，B 已成代码
```

守则文件自己记着：「其中『最终离岛』已被**同日后续**的新方向取代」。

**方向序列**：无限沙盒式经营（原版）→ 限时逃离（我提的）→ **逐岛征服、永久占领、经营群岛**。
第三个是第一个的**放大版**：第二轮明确砍掉的「扩张领土 / 多伙伴 / 终局反击」，以更大的规模回来了。

**机制**：治理规则里明明写着「同一模块 ≥3 次推翻 → 停下重新定义问题，**先数版本号**」。
但**没有任何东西在数**。每次反转时在场的只有"这次的新想法"，前两次已经滚出屏幕。

**数版本号这个动作，需要一个不在对话里的计数器。** 靠记忆去数，等于没数。

**修法**：方向变更单独记一个**一次只能写一行**的 `DIRECTION-LOG.md`（日期 + 一句话 + 作废了什么）。
第 3 行出现的时候，**文件本身就是停手信号**——不依赖任何人记得去数。

## ④ 我明知文档型规则不激活，却只交付了文档型护栏（这条关于 AI 自己）

⚠️ **同根第 2 次**。11 天前已经记过一次「护栏的感受覆盖面远大于实际覆盖面」。那次问题是护栏**覆盖面**不足；这次是护栏的**形状**被交付形态决定了。

**实锤**：我写的护栏**全部在文档层**——7 条硬约束、停手信号、完成定义、交付前自检清单。
而我的长期记忆里早就存着两条：「规则不激活就去改 hook」和「实测规则的自然激活率是 0」。

三天后：7 条硬约束里的**第 1 条**——「不许自作主张增加功能」——被 25 条追加授权逐条绕过。

**机制**：**那一轮我的交付形态是"写一份文档"，所以我能想到的护栏全都是文档形状的。**

这不是忘了那条规则。是它在「写 markdown」这个动作里**不被激活**——它住在"设计治理机制"的语境里，不住在"写一份文档"的语境里。

**这是一个通用病**：记忆按**主题**组织，激活按**动作**发生，两者不对齐。所以你已经学会的教训，会在学它的那个场景之外失效。

**修法**：交付任何含「不许 / 必须 / 停手」的文档时，强制问一句——

> **这条约束的执法者是谁？如果答案是「读文档的人自觉」，它就没有执法者。**

然后把最硬的那一条**移出文档层**：hook、脚本、必填字段、CI 检查，任选其一。一条就够。

## 最高杠杆：②

因为它同时治 ① 和 ③——外部验证数一旦摆在最显眼的那一行，"再加一条授权"和"再反转一次方向"都会立刻显得昂贵。

**立即可做的检查动作**（任何项目，一条命令）：

```bash
grep -c "外部\|试玩者\|playtest\|real user" README.md
```

返回 `0` → 你当前所有的质量数字，只证明"代码按你写的跑"，不证明"东西能用"。

---

## 诚实反束

- **这里看到的是痕迹，不是过程。** 全部证据来自 git log、文件时间戳、文档内容。可能中途真找人试过只是没记录；可能那 27 分钟反转之前有一场看不到的长讨论。
- **这同时也是一份高执行密度的证据。** 77 个 commit 全部完成、1008 项检查全绿、每一轮都带真实按钮路由验证和截图——这不只是失控的证据，也是罕见的交付速度。两件事同时为真。
- **分析者是一个没被验证的验证器。** 写这份复盘的我，正是被推翻的三个方向里第二个方向的作者。我对"方向反复"的判断天然偏向"我那版本该留着"。**这个偏差我没法自己校正。**
- 单场观察不是判决。一次就是一次。
